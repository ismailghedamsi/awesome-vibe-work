# What counts as vibe work?

"Vibe work" is shipped software where **AI agents did the bulk of the coding** — the human directed, reviewed, and shipped, but the machine wrote most of the lines.

## The inclusion bar

A project makes this list when all three hold:

1. **It shipped.** A real, usable app or product — installable, hosted, or in an app store. No mockups, no "coming soon", no dead demos.
2. **AI wrote most of it.** The author states it plainly: in the repo README, a launch post, or an interview. "Built with Claude Code", "100% AI-generated", "vibe-coded over a weekend" — the exact phrasing varies, but the claim must come from the author, not from us.
3. **It's genuinely good.** This is a *great* vibe work collection, not a registry. The app has to be impressive, useful, or culturally notable — something you'd show a skeptic.

## What doesn't count

- **AI-assisted code** where a human still wrote the architecture and most logic (Copilot autocomplete on a normal project).
- **AI wrappers** — a thin UI over someone else's model with no real software underneath.
- **Tutorials and starter templates** for vibe coding (useful, but not *work*).
- **Unverifiable claims** — if nobody official says it was vibe-built, it stays out, no matter how plausible.

## How we verify

Every entry links the evidence: a repo README section, an author blog post, or a launch announcement. Entries whose evidence we couldn't confirm carry `verified: false` in `data/vibe-work.json` and say so. We'd rather flag than guess.
